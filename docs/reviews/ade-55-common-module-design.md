# ADE-55 Depth 전처리·Point Cloud·부피 공통 모듈 설계안

상태: **제안 / 강석현 착수 검토 대기**. 현재 승인된 방법·스키마·기존 함수·실제 샘플은 확보하지 못했다. 계산 코드는 작성하지 않았다. 이 문서는 ADE-54 설계 문서 커밋을 선행 기준으로 하는 별도 ADE-55 검토 브랜치에서 추가했다.

이번 수정본은 원래 두 브랜치를 보존한 `codex/ade-54-ade-55-migration-review`에서 검토했다. 공식 팀 저장소로의 이관은 아직 수행하지 않았다. 공유 필드·단위·출처 구조·오류 코드는 공통 계약 문서를 기준으로 참조하며, 이 문서는 방법별 추가 조건과 검증 가정만 상세히 정의한다.

## 인터페이스와 단계 분리

[공통 규격 제안](common-contract-proposal.md)에 따라 장비 adapter → 공통 입력 validator → preprocess → segment → camera Point Cloud → volume estimator → 공통 결과 serializer를 분리한다. 함수명·패키지 구조·의존성은 실제 저장소 확보 후 기존 인터페이스를 우선 재사용한다.

- 입력 검증: 깊이 의미·단위·해상도·보정 상태·intrinsics·valid mask 확인.
- 유효 깊이 선별: adapter가 명시한 invalid 규칙과 승인된 min/max 범위 사용.
- 노이즈 제거 제안: 유효 이웃만 사용하는 작은 median 필터를 후보로 검토. 커널·최소 유효 이웃 수·깊이 경계 threshold는 승인 필요. 무효 깊이/가려진 구멍을 보간하지 않고 경계·작은 물체가 지워지는지 검증한다.
- 대상/배경 분리 제안: 승인된 수동 마스크 또는 기존 검출/분할 출력과 지지 평면 위 높이 조건을 함께 사용. 기존 모델이 없으므로 새로운 YOLO 학습을 임의로 추가하지 않는다. ROI는 후보 영역일 뿐 최종 대상 분리가 아니다.
- Point Cloud: 정류된 광축 Z의 pinhole 역투영으로 m 단위 카메라 좌표 생성. 왜곡 입력·다른 좌표계 요청은 검증된 보정·변환 없으면 실패.
- 부피: 아래 방법은 팀장 승인 후 조건을 충족한 입력에서만 사용. 여러 estimator를 암묵적으로 fallback하지 않는다.

## 부피 계산 후보 — 지지 평면 위 높이 적분 (제안)

대상은 알려진 지지 평면 위에 놓여 있고, 모든 footprint 위치에서 평면부터 관측된 윗면까지 물질이 연속으로 채워진 height field라고 가정한다. 윗면 전체가 관측되고 내부 공동·돌출 아래 빈 공간·다층 구조가 없어야 한다. 이 조건은 Depth 한 장만으로 증명할 수 없으므로 촬영 프로토콜·대상 종류·기준 형상으로 팀장이 적용 범위를 승인해야 한다.

단일 시점으로 가려진 옆면·바닥·내부 공동을 복원했다고 주장하지 않는다. 열린 surface의 convex hull/mesh를 생성해 무조건 체적으로 판정하지 않는다. 임의 물체의 일반적인 실제 부피를 보장하는 방법이 아니다.

### 방법별 추가 입력 (제안)

공통 계약의 선택적 `volume_request`를 이 부피 방법에 대해 아래처럼 확장한다. 부피를 요청하지 않은 ADE-54 입력 변환 단계에는 이 조건들을 요구하지 않는다.

| 필드 | 제안 |
| --- | --- |
| `method` | `support_plane_height_integral` |
| `plane_basis` | 카메라 좌표에서 평면 원점 o(m), 직교 단위 축 e1,e2와 대상 방향 단위 법선 n. o 및 평면 위 점은 `n·p + offset_m = 0`을 만족해야 함. 물체 윗면 점에 이 평면식을 요구하지 않음 |
| `footprint` | 평면 좌표의 승인된 polygon(m) 또는 고정 grid mask, 외곽/구멍·출처·검증 상태 명시. 단순 이미지 마스크를 전체 실제 footprint로 단정하지 않음 |
| `grid` | 원점·셀 간격(m)·해상도·경계 셀 면적 처리·셀 집계 방식 |
| `assumptions_confirmed` | 대상/촬영 프로토콜의 height field 적용 근거, 완전 윗면 관측 근거 |

새 필드는 ADE-51에 추가 검토가 필요하다. 평면·footprint·가정 확인이 없으면 계산하지 않는다. 초기 검증은 알려진 직사각형 footprint와 셀에 정렬된 형상으로 제한하고, 일반 polygon 경계 셀은 실제 겹침 면적을 명시적으로 계산하는 경로가 검증된 후 허용한다.

### 계산 방식 (제안)

1. 평면·basis 정규화/직교성·좌표계·보정 상태를 검증한다. 평면을 추정한다면 별도 배경점, 추정 파라미터와 잔차·지지점 수를 기록하고 기준 평면과 검증해야 한다. 타깃점만으로 평면을 임의 추정하지 않는다.
2. 각 대상 점 p에 대해 높이 `h=n·(p-o)`, 평면 좌표 `s=e1·(p-o), t=e2·(p-o)`를 계산한다. plane 법선은 대상 쪽을 향해야 한다. 음수/불일치 높이를 조용히 0으로 잘라 실패를 숨기지 않는다. 노이즈 허용 범위는 승인 필요.
3. 사전에 고정한 평면 grid에 투영한다. grid 간격은 **픽셀 크기와 독립적인 실제 길이(m)**다. 각 셀의 유효 윗면 관측 높이를 집계한다. median 후보는 기울기·격자 해상도에 따른 편향이 있으므로 평면/계단 기준 데이터로 승인받는다. 옆면이 섞이면 윗면 조건 미충족으로 판정한다.
4. 승인된 footprint 내부 모든 필요한 셀에 관측이 있는지 확인한다. 보수적인 초기 정책은 coverage=100%이고 빈 셀·가려진 셀은 실패다. 작은 구멍을 채우거나 미관측 셀 높이를 0으로 넣지 않는다. coverage 정책을 바꾸려면 팀장 검토가 필요하다.
5. `V = Σ (셀 높이 h_i × footprint와 겹치는 실제 셀 면적 A_i)`로 m³ 출력한다. 전체 셀은 `A_i=Δs×Δt`다. 점 수·평균 점 간격을 임의로 체적으로 변환하지 않는다.
6. grid·평면·footprint·집계·필터 설정과 coverage를 결과에 보존한다. 격자 세분화에 따른 안정성/기준 오차를 평가한다. 측정하지 않은 불확실도 수치를 만들어 넣지 않는다.

`V<=0`이면 대상/가정/분리 검사를 실패 처리하는 초기 정책을 제안한다. 유효 물체가 없는 입력을 정상 부피 0으로 반환하지 않는다.

### 실패 정책

오류 코드 정의는 공통 계약의 오류 표에 모았다. 마스크 없음, 지지 평면 없음, 대상점 없음, 내부 파라미터 없음, 좌표/단위 모호함, 가려진 윗면, 열린 표면으로만 주어진 입력, footprint 미확인, required 셀 부족은 `status=failure,volume=null`과 구체적 원인으로 출력한다. 검증되지 않은 pose/sync를 사용하는 world 정규화 요청도 실패한다. 실패한 계산의 Point Cloud가 이미 생성됐다면 진단 산출물로 남길 수 있으나 부피 성공으로 표시하지 않는다.

## 검증 계획 (승인 후)

아래 기대값은 수식에 따른 **설계 기준값**이며 실행 결과가 아니다.

| 검증 데이터/조건 | 확인할 항목·기준 | 현재 |
| --- | --- | --- |
| 문서의 합성 2×2 깊이 | mm→m, 카메라 좌표 3점의 기대값 일치 | 미실행 |
| 동일 깊이의 mm/m 인코딩 | 정규화 좌표와 최종 부피 동일 | 미실행 |
| 합성 높이 grid 4×5, 셀 0.01×0.01 m, 높이 0.1 m | V=20×0.0001×0.1=0.0002 m³=200 cm³. Point Cloud까지 검증하려면 알려진 평면/basis/intrinsics로 대응 Depth를 생성하고 footprint를 제공 | 미실행 |
| 기울어진 평면 위 알려진 계단 형상 | 좌표 변환, 셀 높이/면적·격자 수렴, 기울기 편향 | 미실행 |
| 빈 배열 / 모두 invalid / NaN·Inf 유효 처리 | 성공 0이 아닌 입력 실패 | 미실행 |
| intrinsics 누락·fx=0·형상 불일치·손상 파일 | 필드별 원인 오류 | 미실행 |
| 마스크·평면·footprint·필수 pose 누락 | 단계 실패, volume=null | 미실행 |
| footprint 내 구멍·가려짐·옆면 혼합·공동 있는 물체 | 적용 가정 미충족, 부피 성공 금지 | 미실행 |
| 같은 입력·설정·코드 버전 재실행 | 수치와 결정적 메타데이터 동일; 난수 사용하는 단계는 seed 고정 | 미실행 |
| 같은 합성 장면을 robot/mobile adapter로 표현 | 동일 공통 계약·수치. 실제 두 경로 검증과 구분 | 미실행 |
| 승인된 실제 로봇·모바일 각각의 샘플 | 같은 출력 스키마, 부피 단위/방법/상태/원인, 기준 부피와 오차 | 실제 데이터 없어 미완료 |

수치 허용 오차·필터 파라미터·grid 간격·실측 반복 횟수·기준 부피 측정법은 확인 필요다. 기준 부피가 없는 샘플은 실행 가능성만 확인할 수 있고 정확도 검증으로 사용할 수 없다. 합성 데이터 결과는 계산 로직 검증으로만 보고한다.

## 성공 출력 예제 (제안, 합성 기대값)

위 4×5 grid가 모든 가정과 검사를 통과했을 때의 문서용 핵심 출력이다. 실제 모듈을 실행해 얻은 결과가 아니며 전체 필수 메타데이터는 공통 계약 확정 때 추가한다.

## 완료 산출물과 범위

승인 후 공통 모듈, 장비별 adapter 분리, 환경/실행 방법, 입력/성공·실패 출력 예제, 샘플 출처, 재현 명령·로그·기준값 비교, 방법 가정·제약 문서를 제공한다. 실제 로봇·모바일 샘플 및 휴대폰 장치 연결이 없으면 해당 검증은 미완료로 유지한다. 중량 회귀와 Android UI는 추가하지 않으며 중량 오차 10% 달성을 주장하지 않는다.

착수 전 질문은 [조사 문서의 일괄 질문](repository-audit.md#5-팀장-검토-질문-일괄)을 함께 검토한다. 팀장 메시지는 보내지 않았고 승인을 받은 것으로 처리하지 않았다.
