# ADE-54 PC Depth 입력 경로 설계안

상태: **제안 / 강석현 착수 검토 대기**. 승인 근거는 [착수 조사](repository-audit.md)에 정리했으며 현재 발견하지 못했다. 구현·장비 연결·재생 테스트는 아직 수행하지 않았다.

문서 이관 준비: 현재 작업 폴더는 팀 코드 저장소로 확인되지 않은 로컬 문서 저장소다. 공식 URL·기본 브랜치 확인 후 별도 clone에서 기존 팀 입력 형식·규칙에 맞춰 이 문서를 수정한다. 아래 환경·포맷·검증 계획은 학교 PC의 미push 코드나 실제 저장소 구현을 확인한 결과가 아니다.

## 환경 정의

제안: “PC 가상환경”은 Windows PC에서 격리한 Python `.venv`와 저장 Depth 프레임 재생 경로를 의미한다. OS 가상머신·Android 에뮬레이터·휴대폰 USB 연결을 의미하는지는 확인 필요다. 현재 호스트 Python은 3.11.15이나 팀 지원 버전과 SDK 호환성은 미확정이다.

승인 후 실제 저장소에서 잠금 의존성을 구성하고 다음 절차를 검증한다. 아래는 **예정 절차이며 현재 실행 가능한 설치 지침이 아니다**.

1. 승인된 Python·OS·SDK 버전과 공식 지원표를 기록한다.
2. `py -3.11 -m venv .venv`는 3.11 사용 승인 및 launcher 가용성이 확인될 때의 예시다.
3. `.\.venv\Scripts\python.exe -m pip install -r requirements.lock`처럼 승인된 의존성을 설치한다. 현재 이 lock 파일은 없다.
4. 구현 후 결정한 CLI로 manifest 검증 → 단일 프레임 변환 → 연속 재생 → 공통 출력 저장을 실행한다. CLI 이름은 기존 구현 확보 후 확정한다.

## 입력과 재생

실제 입력 형식은 **미확인**이다. 제안 저장 교환 형식은 `manifest.json` + 프레임별 `.npy` H×W 수치 배열이다. 원본 저장 포맷이 확보되면 우선 재사용한다. `.npz`·SDK 녹화 포맷·PNG·RGB·disparity는 명시적 변환 경로가 승인되지 않으면 지원한다고 표시하지 않는다. NumPy를 채택할 경우 object 배열/pickle 로딩은 허용하지 않는 방식을 제안한다.

manifest에는 frame 순서, 배열 파일, dtype/해상도, unit/scale/invalid 규칙, intrinsics 및 보정 상태, 촬영 시각과 clock domain, source/provenance, 선택적 pose/IMU를 포함한다. 스키마는 [공통 규격 제안](common-contract-proposal.md)을 따른다.

원본 manifest와 adapter 정규화 출력의 필드는 구분한다. 공통 문서의 `raw_depth` JSON은 원본 예시 일부이며, 실행 모듈이 출력한 공통 `depth` 배열 예제로 보고하지 않는다. `volume_request`는 ADE-55 단계의 선택적 요청이므로 ADE-54 읽기·변환 성공에 footprint나 부피 방법을 필수로 요구하지 않는다.

장비 adapter와 파일 replay adapter를 분리한다. 장비 없는 실행은 저장 샘플만 사용한다. 실제 샘플이 없으면 별도 synthetic 폴더에 생성 근거·seed·기대값을 기록하고 계산 계약만 검증한다. 문서의 합성 배열 예시는 재생 가능한 샘플 파일로 만들어진 상태가 아니다.

기본 재생 순서는 manifest 순서로 고정한다. 선택적으로 촬영 시간 간격 재생을 지원할지 검토한다. timestamp 누락 시 고정 간격은 재생 설정일 뿐 실제 촬영 시간/동기화 근거가 아니다. 중복 frame ID, 누락 파일, 비단조 시각의 처리 정책도 manifest 검증에 명시한다. clock domain이 다른 timestamp는 그대로 비교하지 않는다.

## 입력 검증과 결과

1. 파일 존재·읽기 가능·형식·손상 여부 확인.
2. Depth가 비어 있지 않은 2D 수치 배열인지 확인; declared dtype·해상도 일치 검증.
3. unit/scale/semantics를 확인하고 m의 광축 깊이로 정규화. 원본 invalid 규칙으로 mask 생성; 유효 깊이가 없으면 원인 오류 반환.
4. 해당 해상도의 intrinsics·왜곡/정류 상태 확인.
5. 촬영 시각·자세는 가용성을 기록하고 stage별 필수 정책 적용. 동기화는 별도 측정 자료가 없으면 unverified.
6. adapter 출력에 장비·원본 수집 경로·실제/합성 출처·checksum 보존.

공통 입력 변환 성공은 부피 성공이나 휴대폰 연결 성공을 뜻하지 않는다. 오류 구조·문서용 입출력 예시는 공통 규격 문서를 따른다.

## 승인 후 검증과 완료 산출물

| 검증 | 기대 결과 | 현재 |
| --- | --- | --- |
| 승인된 실제 저장 프레임 읽기 | 배열·메타데이터 보존, 공통 입력 계약 준수 | 샘플·규격 없어 미실행 |
| mm/m 변환, invalid/해상도 검사 | 같은 물리 깊이가 같은 정규화 출력, 원인 오류 | 구현 승인 전 미실행 |
| 누락·손상·형식 미지원·빈 입력 | 실패 상태와 필드/코드, 비정상 종료 | 구현 승인 전 미실행 |
| 연속 재생·같은 입력 재실행 | 순서와 수치 출력 동일; replay 시각 같은 비결정 필드는 비교 제외 | 구현 승인 전 미실행 |
| capture/pose 시간 검증 | clock mapping·offset·허용 오차 자료에 따른 판정 | 자료 없어 미완료 |
| 실제 외장 카메라 PC 입력 | 모델·SDK 버전·깊이 의미·프레임 정상성 | 장치 확인 전 미완료 |

완료 시 환경/의존성 버전과 실행 명령, 샘플 출처·checksum, manifest·정규화 출력, 재생 로그(frame ID·유효점·오류·sync 상태), 실행 시각·종료 코드·재현 결과를 남긴다. 현재는 이 완료 산출물을 충족하지 않았다.

## 실제 휴대폰 연결 점검 목록

- [ ] 정확한 카메라 모델·firmware·USB VID/PID와 최신 팀 장비 결정.
- [ ] Android 기종·OS·CPU ABI, USB host/OTG 지원, 연결 방식·전원·케이블 조건 실측.
- [ ] 해당 장비 및 설치 SDK 버전의 공식 Android 지원/배포·라이선스·API 자료 확인.
- [ ] 권한·연결/해제·재접속·앱 생명주기·실제 depth stream 개시 확인.
- [ ] 출력 dtype·해상도·fps·깊이 단위·sentinel·intrinsics·정류/정렬 상태 확인.
- [ ] IMU↔Depth 외부 보정과 sensor/host clock mapping, offset·jitter·동기화 허용 오차 측정.
- [ ] 대역폭·프레임 손실·열·배터리·장시간 수집 조건 기록.
- [ ] PC 재생과 실기기의 공통 스키마 비교; 실패 처리·두 경로 차이 기록.

모든 항목은 미완료다. 사용자 제공 모델명만으로 USB/SDK/Android 지원 여부를 판정하지 않는다. Android 화면 구현은 이가영 담당이며 본 작업 범위에서 제외한다.
